# strategic_GNE_selection — fair GNE selection for the bilateral P2P game

Searches for *fair* generalized Nash equilibria (GNEs) of the cyclic four-prosumer
IEEE33 bilateral trading game (24 h horizon, 1 h resolution) **without** exhaustive
parametric critical-region enumeration. Candidates are generated by convex
optimization and each one is independently checked by unilateral best responses.

## Layout

```
p2p-energy-trading-illustrative/
  scenarios.py, config.py, ...            # original study (used for scenario data)
  structures/ieee33_4_cyclic/results/     # existing results tree (must exist)
  strategic_GNE_selection/
    strategic_GNE_selection.py            # the suite (StrategicGame, reduction, metrics, caching)
    strategic_GNE_selection_demo.ipynb    # main workflow: change DATE, Run All
    strategic_GNE_selection_reduction.ipynb  # optional stage-by-stage reduction audit
    test_strategic_GNE_selection.py       # unit tests (mocked adapter, no Gurobi needed)
    p2p/                                  # LQ game adapter: build_game, load_ieee33, evaluated_costs, vgne
    RESEARCH_DESIGN.md                    # method and caveats
```

## Requirements

- The `p2p` conda env (Python 3.10) with `gurobipy` (licence), `numpy`, `scipy`, `pandas`, `pandapower`.
- The DyNECT Python package at `~/Documents/Github/dynect_py_p2p` (used for `DynLQGameTV`
  condensation and `MpAVI`; the notebooks add it to `sys.path`).

## One-date workflow

1. Open `strategic_GNE_selection_demo.ipynb` **from this folder** and set `DATE` in the first code cell.
2. Restart the kernel and Run All. The first cell resolves the project root, checks that the
   `p2p` adapter next to the notebook is the one imported, and performs a write/read probe.
3. A date-specific reduction is built and saved (or reused if the cached model matches the
   scenario, seed, resolution and reduction settings) and reloaded with a matrix check.
4. Cost separability, model/physical objective consistency and artificial regularization are
   audited; the notebook stops if this check fails.
5. Candidates: equal-weight vGNE, no-trade benchmark, regularized minimax, max-min savings,
   random positive cost weights, Nash bargaining (Frank–Wolfe) plus its weighted refinement,
   Pareto refinement and reciprocal trade-schedule search.
6. All candidates, `comparison.csv` and `experiment_manifest.json` are saved under
   `structures/ieee33_4_cyclic/results/<DATE>/fair_gne/1h/`.

```
results/<DATE>/fair_gne/1h/
  reduction/reduced_game.npz, reduction_audit.json
  cache/*.npz                         # solver cache, keyed on model + options
  selection/comparison.csv
  selection/experiment_manifest.json
  selection/diagnostics/cost_audit.json
  selection/candidates/*.npz
  selection/analysis/reduction_notes.md   # written by the reduction notebook
```

The suite refuses to create a second results tree: `structures/ieee33_4_cyclic/results/`
must already exist at the project root. Existing `centralized.json`, `distributed.json`,
`no_trade.json` and `fairness.json` are only read, never modified.

## Scientific qualifications

- The 24h/1h model approximates the original 30-minute dynamics and is active-power only.
  A redundancy certificate at 1 h does **not** carry over to 30 min.
- `verified_GNE=True` means the candidate passed numerical unilateral best-response tests for
  all physical and trading constraints of the *saved* game. It is not an enumeration of the
  equilibrium set, nor a proof of global fairness optimality or pairwise renegotiation stability.
- Strict separability is needed for the Pareto-to-GNE argument; the cost audit checks cross-player
  Hessian blocks and physical-cost perturbations, with zero artificial regularization by default.
- Nash bargaining scores are defined only for strictly positive individual savings. Unconverged
  Nash iterates remain diagnostic and are labelled as not verified if they fail best-response tests.
